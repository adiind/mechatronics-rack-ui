## Animation rules

Shared clock and physical x-order coordinate all seven ropes. Render frames with pure deterministic functions also used by server-supplied browser preview, rather than two inconsistent animation implementations. Separate state interpretation, rendering, output transport, persistence, and HTTP/UI.

- Online idle: slow blue/teal watery movement continuously, subdued and attractive.
- Preparing: cyan rising sweep, only when telemetry says PREPARE (do not invent heating stages from temperature alone).
- Printing: readable progress waterline, teal/green filled region, dark blue remainder, rain droplets and small splashes. Percentage remains legible while moving.
- Paused/intervention: amber breathing with a distinct stable marker; errors: stronger orange-red breathing, no strobe. Error and pause must not look like routine idle.
- Fresh completion: short green celebration/ripple, then stable green ready-for-collection signal. Initial FINISH, reconnect FINISH, historical job names, and process restart must not trigger celebrations. Retained FINISH does not prove the bed was cleared. Offer a local Acknowledge collected action that changes only display bookkeeping; do not send any command to printers. A new observed active job clears acknowledgment.
- Disconnected/stale: clearly different dim slate/purple heartbeat, no stale percentage; absent/unknown state never defaults to available. Source timestamp measures message receipt, not per-field change. Use 120-second timeout, robust bad/missing/future timestamp handling and Pi local timezone.
- Global idle wave gently flows across eligible ropes. New genuine start/completion may send one brief spatial ripple with propagation delay based on physical order. It must not override error/pause/offline markers or erase progress. Bound event queues, deduplicate, don't replay after a telemetry gap. Persist lifecycle bookkeeping as needed for restarts. Prefer correctness over speculative job identity; identical names aren't reliable IDs.
- UI animation playground: explicitly labeled simulated state/progress for chosen bay or all bays, idle/prepare/printing/paused/error/finished/offline; preview only, never alters real telemetry or lights. Speed, brightness (keep current hardware ceiling), ripple toggle, reduced motion and quiet dimming setting. Do not claim unsupported local firmware effects.
